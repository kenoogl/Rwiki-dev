# Tasks Document

本文書は dual-reviewer v2 取得処理の実装タスクを列挙する。各タスクは `requirements.md` の機能要件と紐づく。実装は本 spec の `design.md` が参照する v2-acquisition-design.md の原則に従う。

## 実装タスク一覧

### T1：v1 取得スクリプトの撤去 / 隔離判断

- 対象：`dual-reviewer-rebuild/scripts/track_runs/` 配下、`dual-reviewer-rebuild/runtime/executors/` 配下、`dual-reviewer-rebuild/runtime/execution_v2/analyzers/` の規則照合実装。
- 内容：規則ファイル依存の処理を撤去または無効化する。`build_rule_matched_analysis` 系メソッドの取り扱いを決める。
- 関連要件：AC-4。

### T2：方式 B（Claude Code CLI）呼び出しの基盤実装

- 内容：`claude --print --model <model>` を呼び出し、入力をパイプし、出力を捕捉する基盤 Ruby メソッドを実装。
- 関連要件：FR-7。

### T3：主役セッション起動コードの実装

- 内容：T2 の基盤を使い、主役（Opus）用のセッションを起動。プロンプト、入力ファイル組立、出力受け取りまでを 1 関数として実装。
- 関連要件：FR-1、FR-2、FR-3、FR-4。

### T4：敵対役セッション起動コードの実装

- 内容：T2 の基盤を使い、敵対役（Sonnet）用のセッションを起動。主役の出力を入力として受け取る β 逐次方式を実装。
- 関連要件：FR-1、FR-2、FR-3、FR-4。

### T5：判断役セッション起動コードの実装

- 内容：T2 の基盤を使い、判断役（Opus、別セッション）用のセッションを起動。主役と敵対役の両出力を入力として受け取る。
- 関連要件：FR-1、FR-2、FR-3、FR-4。

### T6：プロンプトテンプレートの設計と実装

- 内容：3 役分のプロンプトテンプレートを `requirements.md` の FR-3 に従って書く。テンプレートはバージョン管理可能な形で保存。
- 関連要件：FR-3、FR-5（prompt_version メタデータ）。

### T7：構造化区切りによる入力ファイル組立の実装

- 内容：`<file path="...">...</file>` 形式で複数ファイルを 1 つの入力に組み立てる。
- 関連要件：FR-4。

### T8：4 フィールド Markdown 出力の解析実装

- 内容：LLM の出力を 4 フィールド（重大さ / 対象箇所 / 説明 / 根拠）に分解し、構造化データに変換する。敵対役の場合は種別フィールドも処理。判断役の場合は判断ラベルも処理。
- 関連要件：FR-3、FR-5。

### T9：3 方式（single / dual / dual+judgment）の構成実装（再利用方式）

- 内容：1 ケースあたり主役 1 回 + 敵対役 1 回 + 判断役 1 回の呼び出しで 3 方式の出力を構成する仕組みを実装。
- 関連要件：FR-9。

### T10：メタデータ収集と保存

- 内容：10 項目すべてを各取得に付与し、JSON / Markdown 両方に記録。
- 関連要件：FR-5。

### T11：ログ詳細保存の実装

- 内容：各 LLM 呼び出しの入出力全体（プロンプト、出力、エラーログ）を保存。
- 関連要件：NFR-2。

### T12：リトライ機構の実装

- 内容：軽微な失敗（タイムアウト、一時的エラー）時の自動リトライ最大 3 回を実装。
- 関連要件：FR-6。

### T13：反復取得（各設定 3 回）の実装

- 内容：同じ設定で 3 回繰り返し取得する仕組みを実装。
- 関連要件：FR-6、AC-3。

### T14：subscription 利用枠監視の実装

- 内容：方式 B 利用時の subscription 利用枠の消費状況を取得前後に記録。閾値超過時は警告。
- 関連要件：NFR-3。

### T15：取得結果の v2 専用パスへの保存

- 内容：取得結果を `experiments/v2/{track}-track-runs/{case}/{mode}/...` のような階層で保存。
- 関連要件：FR-8。

### T16：取得バッチ実行スクリプトの実装

- 内容：複数ケース × 3 方式 × 3 反復を完全逐次で実行する取得バッチスクリプトを実装。
- 関連要件：FR-6、FR-7、AC-1。

### T17：テスト戦略の設計と実装

- 内容：実 LLM 呼び出しを含むためテストが難しい。モックを使った単体テストと、少数の実取得サンプルを使った結合テストの両方を設計。
- 関連要件：すべてのタスクの品質保証。

## 実装順序の方針

- 基盤（T1、T2、T7、T8）を先に整える。
- 役割実装（T3、T4、T5、T6）。
- 3 方式構成（T9）。
- メタデータ・ログ・リトライ・反復（T10〜T13）。
- 運用（T14、T15）。
- バッチ実行（T16）。
- テスト（T17）は各段階で並行に。
