> ### 3.3 手戻り区分（起点フェーズの記号＋深さの数字）
>

>

>

>
> - **I-0**：実装内で吸収
> - **I-1**：タスク段への差し戻し
> - **I-2**：設計段への差し戻し
> - **I-3**：要件段への差し戻し
> - **I-4**：意図段への差し戻し
>
> 本対象システムの原典レビュー記録は旧表記の **A／B／C／D**（A＝実装内吸収、B＝設計差し戻し、C＝要件差し戻し、D＝意図差し戻し）で記録されており、これは実装段を起点とした特殊形のみを扱う表記である。新表記との対応は次のとおり：

> | C        | I-3     | 要件段への差し戻し             |

### 3 つの軸の区別

レビュー所見は本来、独立した 3 つの軸を持ちます：

1. **重大度（severity）**：所見の深刻さの段階
   - 要件・設計：CRITICAL／ERROR／WARN／INFO（4 段階）
   - タスク・実装適合：致命／重要／軽微 または P1／P2／P3（3 段階）
   - 論文 §4.3 では High／Medium／Low の 3 段階に粗統一
2. **対応優先度（action priority）**：そもそも対応するか
   - 要件・設計・タスク：must-fix／should-fix／leave-as-is（3 段階）
   - 実装適合：原典には独立の語彙が無く、severity でほぼ代用されている
3. **手戻りの深さ（depth）**：対応がどこで吸収されるか
   - 新スキーム：起点フェーズ記号（R／D／A／I）＋深さの数字（0／1／2／3／4）
   - 要件・設計・タスク段は原典に depth 表記が無く、新スキームで暗黙的に変換している

- 実装適合段では「対応優先度」軸が原典に欠落しており、severity で代用されている
- 要件・設計・タスク段では「深さ」軸が原典に明示されていない

### 統一の方向

3 つの軸を独立に明示する：

- **重大度**：3 段階（High／Medium／Low）に統一。本文 §4.3 ですでに採用済みのマッピングを全フェーズに適用
- **対応優先度**：must-fix／should-fix／leave-as-is の 3 段階を全フェーズに統一。実装適合段にも導入する（次バージョン実装の課題）
- **深さ**：本文 §3.3 の新スキーム（X-Y）をそのまま全フェーズに適用

各所見はこれら 3 つの値をすべて持つ（例：「CRITICAL／must-fix／R-0」のような形）。
