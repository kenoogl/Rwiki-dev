# Brief

## 概要

dual-reviewer の取得処理を、規則ファイルに依存する決定論的な処理から、実 LLM 呼び出しによる真のレビュー取得に置き換える。

この変更は、v1 で発見された汚染（規則ファイルが件数構成を縛り、観測結果が事前固定された出力になっていた問題）を根本から取り除くために必要である。

本 spec は、v2 取得処理の意図、要件、設計、実装タスクを一体として管理する。

## 背景

v1 では、次の 5 層の事前設定によって取得結果が縛られていた。

1. 主役・敵対役・判断役のプロンプトに具体トピックが書き込まれていた。
2. ヒューリスティック規則ファイルの方針が「主役 1〜2 件、敵対役 0〜1 件」と件数を上限固定していた。
3. 各ケースの規則ファイルが共通の三つ組語彙（boundary / update-order / parameter-caveat）を持っていた。
4. Ruby ランタイム層が規則ファイルを決定論的に照合して発見を生成していた。
5. 論文計画書に観測結果が先取りで書かれていた。

その結果、3 領域・3 言語・改修反復にわたって「単独 2 件・二重 3 件・二重+判断 3 件」という偽の規則性が観測された。これは LLM レビューの本質的な性質ではなく、規則設計の帰結だった。

v1 の取得結果は archive に分離済みであり、v2 では実 LLM 呼び出しに置き換えた取得処理で真の値を観測する。

## 想定利用者

- dual-reviewer の開発者。
- dual-reviewer の方法論研究者。
- 仕様駆動開発を意図駆動で進めたい研究者。

## ゴール

1. 規則ファイルへの依存を完全に撤廃する。
2. 3 方式（single / dual / dual+judgment）の比較の真の差を観測可能にする。
3. 取得処理の再現性を確保する（温度ゼロ、構造化入力、メタデータ完全記録）。
4. 取得結果を構造化形式で保存し、後続の集計・比較・論文化に再利用できるようにする。
5. cc-sdd 連携に対応する spec パッケージとして整える。

## Non-Goals

1. 別 LLM プロバイダ（GPT 系など）との比較（v3 以降の計画）。
2. 役割間の対話形式の取得（v3 以降の計画）。
3. 比較軸を「役割の数」以外（モデル間、プロンプト間、温度間など）に変える設計（v3 以降の計画）。
4. v2 取得の自動化された支援。取得自体は手動で起動する。dual-reviewer 自身の支援機能は v2 で再構築中のため使えない。
